# ADR-0001：本地剪贴板管理器的首期架构、数据契约与运行约束

本应用用于在 macOS 中保存和重新使用剪贴板内容，降低依赖旧版 Paste 后因系统升级、权限或启动状态不透明而失效的维护成本。本文提出原生、单进程、本地存储的架构，并具体定义内容恢复、权限降级、后台运行和验收方法；本期明确不包含 iCloud。

## 2. 背景、证据与不能据此得出的结论

### 2.1 本机参考对象

参考对象是 /Applications/Paste.app，版本 2.4.1，构建号 52，2018 年构建，主可执行文件为 x86_64。曾观察到其通过 Rosetta 在 arm64 Mac 运行。系统检查曾报告 macOS 27.0.1。

本机证据包括：

| 证据 | 能确认什么 | 不能确认什么 |
| --- | --- | --- |
| 主应用 Info.plist 的 LSUIElement=true | 使用菜单栏/agent 应用形态 | 不能保证计时器不受节流，也不代表崩溃自动重启 |
| PasteCore 的 Pasteboard.startMonitoring() 机器码 | 重复 NSTimer，间隔 0.3 秒、容差 0.03 秒 | 不能据此承诺不漏记快速连续复制 |
| synchronize(changeToken:) 对 changeCount 的比较及 pasteboardItems 读取 | 通过变化计数轮询剪贴板 | 不是完整历史事件订阅 |
| PasteboardItem.dataByType | 同一项目保存多种表示 | 不证明所有私有类型都可以长期恢复 |
| Core Data 数据库实体与关系 | 历史、内容表示、来源应用、设备、Pinboard 等概念 | 不应直接照抄旧表名或向旧库写入 |
| 单独的 search.db 中的 documents 表 | 搜索内容另有保存 | 未发现足以确认 FTS 的表结构，不能称已确认使用 FTS |
| LoginItems 中的辅助 app、SMLoginItemSetEnabled 引用 | 旧式登录启动路线 | 无足够证据认定存在持续守护主程序的看门狗 |
| 设置、历史面板和本地化资源 | 功能、选项及渠道共享文案 | 资源存在不等于当前渠道全部启用 |
| 之前的数据库时间和日志 | 部分时段确实新增内容 | 不证明用户当时的面板、快捷键和自动粘贴完整成功 |

2026-10-30 的诊断曾看到输入监听被拒绝；稍后输入监控记录变为允许，而发送事件权限有更早的拒绝记录。这些观察不构成已复现、已修复的统一根因。新应用必须避免把单条旧权限记录解释为所有失败的原因。

### 2.2 开发环境事实

当前检查时命令行开发目录是 /Library/Developer/CommandLineTools，可见 SDK 为 13.3，xcodebuild 没有连接完整 Xcode。常见应用目录及 Spotlight 查询未定位到完整 Xcode，但不能由此断言用户没有安装。

实施前确认完整 Xcode 的实际位置、SDK 版本及所支持的系统范围。本文件不自动修改 xcode-select、不安装软件、不创建证书。运行时版本判断不能让旧 SDK 编译一个不存在于该 SDK 的声明。

## 3. 问题定义、目标与范围控制

### 3.1 用户问题

用户需要一个可维护的本地剪贴板管理器：复制内容后能找回、搜索、收藏并重新粘贴；当权限、快捷键、磁盘或运行状态出问题时，应用应说明具体故障而不是保持一个看似正常的进程。

### 3.2 首期目标

1. 正常使用桌面应用时，在允许读取的前提下保存稳定的剪贴板快照。
2. 保存可恢复的多项目、多表示内容，而不只保存展示文字。
3. 历史面板可通过菜单栏和自定义全局快捷键访问。
4. 可搜索、收藏、删除，并限制历史容量。
5. 恢复系统剪贴板与自动粘贴分别报告结果。
6. 关闭面板后继续记录；登录启动遵守系统授权；睡眠唤醒后恢复。
7. 所有产品内容存储在本机，不依赖账号、服务器或云配置。
8. 记录失败有可理解的状态和不含正文的本地诊断。

### 3.3 首期功能分级

以下是按 Q02 用户答复锁定的首期分级；具体 UI 参数仍可在不改变行为契约的前提下调整。

| 功能 | 建议首期 | 具体边界 |
| --- | --- | --- |
| 文本、富文本、图片、链接 | 是 | 支持明确列出的表示类型，不承诺所有应用私有格式 |
| 文件 | 是，仅引用 | 不归档副本；原文件不可用时明确失败 |
| 颜色专用卡片 | 后置 | 普通文本中的颜色值仍可按文本记录 |
| 历史容量、删除、清空 | 是 | 收藏保护与清空历史分开 |
| 来源应用和时间 | 是 | 来源允许未知并标明推断性质 |
| 搜索 | 是 | 中文子串、正文、标题、来源名称 |
| Pinboard | 是 | 命名、排序、固定/解除固定 |
| 手动恢复与自动粘贴 | 是 | 权限不足时仍提供恢复剪贴板 |
| 纯文本模式 | 是 | 单次覆盖与全局默认 |
| 呼出与收藏切换快捷键 | 是 | 注册冲突可见，不默认拦截所有按键 |
| 快速粘贴编号快捷键 | 后置 | 首期用选择和 Return，不额外占用编号组合 |
| 忽略应用及特殊标记 | 是 | 落库和索引之前过滤 |
| 内置预览 | 是 | 文本与图片本地预览，不执行 HTML |
| Quick Look、系统分享菜单 | 后置 | 不影响核心内容恢复 |
| 登录自启和菜单栏设置 | 是 | 用户主动开启，系统实际状态可见 |
| 音效和完整使用教程 | 后置 | 保留最少必要的首次运行说明 |
| iCloud、账户、远程同步 | 否，用户确定 | 无占位云界面、无容器配置、无远程队列 |

### 3.4 明确非目标

本期不实现远程服务、登录账户、订阅支付、遥测上传、AI/OCR、跨设备同步、iOS 客户端、自动更新平台、剪贴板内容执行、后台 root daemon、键盘记录器、全机文件扫描。旧 Paste 数据迁移不是本次隐含要求；需要时另做只读、一致快照导入设计。

用户已选择本机自用。Mac App Store、对外公证分发、Intel 和旧版 macOS 的支持均不属于首期验收承诺。

## 4. 应用身份、账户与签名

### 4.1 必须区分的五个概念

| 名称 | 含义 | 本机本地版本的关系 |
| --- | --- | --- |
| Bundle ID | 项目和系统用来识别 app 的字符串，如 local.charslee.localclips | 需要选一个稳定、避免冲突的值；不需要为这个字符串买域名 |
| 开发者后台 App ID | Apple 团队中注册的应用身份及能力关联 | 普通本地版本不以手工注册为前置条件；受管能力和正式分发再按规则配置 |
| Apple 账户 | 开发者本人或设备使用者的账户 | 应用本身不要求账户登录；获取开发工具和证书是另一层事情 |
| 代码签名 | 为二进制及资源建立可验证的完整性和身份 | 本地构建也需要适当签名，尤其 Apple Silicon；本地运行签名不等于 Developer ID |
| Developer ID / 公证 | 独立分发时作者使用的身份和 Apple 检查流程 | 给别人正常下载安装时再纳入发布流程，不由每位用户办理 |

Mac 的本地 ad-hoc 签名与 iOS 的 Ad Hoc 分发不是同一件事。不得套用 iOS 的设备注册或到期结论解释普通 macOS 本地 app。

### 4.2 建议的本期身份策略

按用户已选择的本机自用路线：使用自己的 Bundle ID 和固定安装位置；不添加 CloudKit、推送、App Groups 或其他受管能力。先验证本地运行签名，再验证重编译后的权限身份和登录启动。

可调示例标识为 local.charslee.localclips，工作名 LocalClips。示例标识不代表已经占用开发者后台记录；实施前检查本机冲突。不要沿用 com.wiheads.paste，也不要与旧应用共用数据目录。

本机运行可以从 Xcode 的本地运行签名开始，但 ad-hoc 二进制的内容变化可能改变系统识别的代码要求。因此：

1. 相同 Bundle ID 不等于权限必然延续。
2. 不承诺重编译后永远不需要重新授权。
3. 如采用固定本地签名身份，仍需验证 TCC 和 ServiceManagement 对它的实际接受情况。
4. Developer ID 是正式独立分发的路线，不得在文档里偷换为本地开发的付费前置条件。
5. 不写入 TCC 数据库、不关闭 SIP、不修改 Gatekeeper 全局策略来满足验收。

### 4.3 分发路线矩阵

| 路线 | 开发者需要配置什么 | 使用者是否需要注册 App ID | 当前状态 |
| --- | --- | --- | --- |
| 本机自己构建 | Bundle ID、构建签名、系统必要授权 | 否 | 本期选定 |
| 发布源代码，别人自己编译 | 构建说明；每个人处理本机身份和授权 | 不因源码本身自动要求 | 后续可选 |
| 网上发已签名、公证 app | 作者的 Developer ID、公证及发布配置 | 否 | 本期排除 |
| 无正式分发身份的下载包 | 可能无法按默认信任流程启动，不能承诺零提示安装 | 否 | 不作为正式体验承诺 |
| Mac App Store | 开发者计划、后台身份、沙盒及商店要求 | 否 | 本期排除，未来选择时重审控制架构 |

“网上下载后没有注册步骤”通常说明作者已把 Bundle ID 和构建身份放进应用包，不意味着应用没有这些字段。

### 4.4 签名验证门槛

实施阶段记录构建 A 和修改后的构建 B 的 Bundle ID、签名种类及 designated requirement；在同一安装位置验证启动、读取权限、自动粘贴权限和登录项状态。不采集或输出任何私钥。

若本地签名被 SMAppService 拒绝，必须报告错误和真实状态。本草案允许提供系统手动添加登录项的本机使用路径，但不能把手动配置伪装成应用内注册成功；两条路径都必须经过实际登录验证，不能仅凭开关状态通过验收。

相关事实来自 Apple 的 Bundle ID、App ID、代码签名、公证及 ServiceManagement 文档，链接见本文末尾。旧技术说明解释机制，不能单独作为 macOS 27 实际通过的证明。

## 5. 总体架构与备选方案

### 5.1 建议决策

采用 Swift、SwiftUI 与 AppKit 的原生应用。设置及内容视图优先 SwiftUI；菜单栏、面板生命周期、焦点和剪贴板使用 AppKit。首期一个用户会话主进程，Core Data 保存本地历史；没有网络产品功能。

~~~mermaid
flowchart TD
    PB[系统剪贴板] --> REC[ClipboardRecorder]
    REC --> FILTER[类型与隐私过滤]
    FILTER --> STORE[HistoryStore]
    STORE --> UI[HistoryPanel]
    HOT[HotkeyController] --> UI
    UI --> PASTE[PasteController]
    PASTE --> PB
    PASTE --> TARGET[用户选定的目标应用]
    PERM[PermissionState] --> REC
    PERM --> PASTE
    LIFE[应用生命周期与登录项] --> REC
~~~

### 5.2 为什么选择这条路线

| 备选 | 优点 | 本期不优先选择的代价或原因 |
| --- | --- | --- |
| 全部 SwiftUI | 界面开发统一 | 面板焦点、窗口层级和快捷键仍需 AppKit 集成 |
| 原生 AppKit + SwiftUI | 平台接口直接，焦点行为可控 | 需要明确主线程与后台数据操作的隔离，选用 |
| Electron 等跨平台壳 | Web UI 开发方便 | 核心仍是 macOS 专属能力，本期多一层运行时与桥接成本 |
| UI + 常驻 recorder 双进程 | 进程隔离，UI 崩溃不必停止采集 | 身份、权限、IPC、升级与数据并发显著复杂，未有已确认需求 |
| root daemon | 系统级进程 | 剪贴板属于登录用户图形会话，提升到 root 不能解决产品问题 |

### 5.3 模块职责与最小接口

| 模块 | 调用者可以请求什么 | 模块内部承担什么 |
| --- | --- | --- |
| ClipboardRecorder | start、pause、resume、观察状态 | 计数检查、读取一致性、过滤、有限重试与自身写入识别 |
| HistoryStore | ingest、query、delete、pin、clearHistory、观察变化 | 持久化、去重、容量回收、收藏关系、版本兼容 |
| HistoryPanel | present、dismiss | 搜索、分页、键盘选择、来源及状态展示 |
| PasteController | restore、paste；观察阶段结果 | 表示转换、写回验证、焦点恢复、权限检查与事件发送 |
| HotkeyController | register、update、unregister | 快捷键保存、冲突和实际注册状态 |
| PermissionState | refresh、用户触发请求 | 剪贴板策略、控制权限与无法确定状态 |
| LoginController | setEnabled、refresh | ServiceManagement 注册、实际状态和错误 |

模块接口必须包含失败语义与顺序约束，不只列出几个函数名。首期不为每个系统类建立抽象工厂；只有真实变化或已有验证需求时再引入适配位置。

### 5.4 并发规则

1. UI、面板、前台应用操作和需要主线程的平台对象在 MainActor 上操作。
2. 对 pasteboard 的读取串行化，避免两个采集轮次同时生成快照。
3. Core Data 对象不跨 context/actor 传递；跨模块返回不可变值或稳定对象 ID。
4. 内容解码、摘要和索引提取尽量在受控后台工作中进行。
5. 后台工作不无界排队。一次读取未结束时，将后续计数变化合并为“需要再检查”，不为每个 tick 新建任务。
6. Swift Task 的取消不保证中断同步系统 IPC；不能用简单超时包装宣称底层 pasteboard 调用已经停止。
7. 关闭面板不会销毁 recorder；暂停采集会取消后续采集调度并释放相应活动声明。

## 6. 采集契约与变化检测

### 6.1 基本算法

建议采用单一重复计时器，以 300ms 为起步周期、30ms 为容差。这是可调默认，来自旧版机制的合理起点，不是新应用已经测得的最佳能耗或完整性保证。AppKit 的 general pasteboard 为数据来源。

每轮的语义顺序如下：

1. 检查用户是否暂停、会话是否适合采集、存储是否可写及已知访问策略。
2. 读取变化计数；未变化时结束，不重新读取正文或更新数据库。
3. 读取项目和类型元数据；先判断忽略规则与特殊标记，再读取受支持的内容表示。
4. 在受控限额内生成内存中的不可变快照。
5. 再次读取变化计数；前后不一致时丢弃整份快照。
6. 最多进行 2 次立即重试；继续变化时等待下个调度周期，不忙等。
7. 识别本应用恢复操作产生的写入，计算版本化内容摘要。
8. 将完整快照交给存储模块，事务成功后才能报告“已保存”。

读取失败、读取到空内容、所有类型不支持、因隐私规则跳过和存储失败是不同结果。记录各自的原因码，不能统一显示为“没有新内容”。

### 6.2 变化令牌不是历史日志

变化计数只用于当前进程与当前 pasteboard 状态比较，不作为持久业务 ID。系统重启或 pasteboard 服务变化后，不假定数值仍保持跨会话单调。

假设 t=0 读取旧内容；t=50ms 复制 A；t=100ms 复制 B；t=150ms 复制 C；t=300ms 才下次读取，应用可能只能获得 C。对此应记录为接口限制，不得以“计数增加 3”伪造三份历史。

首期验收针对保持足够时间的稳定内容，同时单独测量快速复制时的实际表现。全局监听 ⌘C 不能补全所有写入，因为脚本、截图、后台程序和 Universal Clipboard 也能改变剪贴板。

### 6.3 初次启动、暂停和恢复

建议默认不追溯首次启动前的当前剪贴板内容：建立计数基线后开始记录之后的变化，避免把用户未预期的既有敏感内容立刻落库。手动“保存当前剪贴板”可作为后续明确操作，不隐含加入首期。

用户暂停时取消采集；恢复时建立新基线，不补记暂停期间内容。重启后仍保持用户明确选择的暂停状态。系统睡眠引起的暂时停止不写成用户主动暂停。

睡眠唤醒后：若没有用户暂停，刷新权限和存储状态，重新检查变化；当读取到的当前内容与已知最后内容不同且通过过滤时可以采集。无法知道睡眠期间被覆盖的中间内容，不能宣称补齐。

### 6.4 大数据与限额

以下为首期可调默认，修改时同时更新界面说明和测量条件：

| 项目 | 起步值 | 超限行为 |
| --- | --- | --- |
| 单个表示 | 32 MiB | 不保存不完整快照，显示“内容超过大小限制” |
| 一次快照合计 | 64 MiB | 整份跳过，不静默截断为半张图或半个文件列表 |
| 一次快照项目数 | 100 | 整份跳过并说明原因 |
| 每项目表示数 | 32 | 先依据支持列表筛选；仍超限则跳过 |
| 采集并行度 | 1 | 合并后续检查请求 |
| 一致性立即重试 | 2 次 | 交给下一调度周期 |

系统接口可能在完整数据返回后才允许应用确认大小。这些限额能限制长期持有和落库，并不能证明可以在 IPC 层提前阻止所有大对象分配。应从类型元数据、已知长度和受支持格式策略尽量减少不必要读取；异常来源不能让主面板无期限卡住。

## 7. 内容表示与恢复格式

### 7.1 快照的结构

一次快照包含有序的项目；每个项目包含有序的类型标识与原始字节。保留项目顺序和表示偏好顺序。显示主类型只用于展示，不覆盖原始数据。

| 内容类别 | 首期保存方向 | 展示和恢复约束 |
| --- | --- | --- |
| 纯文本 | UTF-8/系统 string 表示 | 保留原始换行与 Unicode，不在原始数据上强制 trim |
| 富文本 | 可用的 plain text、RTF、RTFD、HTML | 记录明确支持的表示；HTML 预览和转换不能执行脚本或加载远程资源 |
| 图片 | 原有的受支持 PNG、TIFF、JPEG 等表示 | 原始恢复不以缩略图替代；限制解码像素总量 |
| 链接 | URL 表示及可用文本/名称 | 不为生成预览访问网站 |
| 文件 | Q03 已确定为仅引用 | 文件 URL 不等于文件内容备份 |
| 颜色 | Q02 已确定后置专用支持 | 普通文本颜色值仍按文本处理 |

最终支持表必须通过接收端验证，包括 Finder、TextEdit 和浏览器。不能简单保存所有私有类型：有的类型只是短期承诺、进程引用或包含与用户复制意图无关的元数据。

### 7.2 首期支持列表原则

采用明确的类型支持列表及兼容规则；对未知类型不执行动态反序列化。不使用允许任意类的归档解码，不执行文件承诺，不通过网页抓取补齐数据。

对一份内容，如果至少存在可完整恢复的受支持表示，可以保存该受支持子集；这与因大小超限导致已支持数据被截断不同。界面不得宣称完整保留所有来源应用私有功能。只有图片展示没有可恢复字节时，不将预览当成成功捕获。

### 7.3 纯文本规则

顺序为：现成的纯文本表示；受控 RTF 转换；无网络、无脚本的 HTML 文本提取。不能靠浏览器加载 HTML 再提取正文。仅图片内容不自动 OCR；仅文件列表不自动以路径文本替代文件引用。

全局“始终纯文本”只影响恢复/粘贴，不破坏已经保存的原始表示。单次纯文本操作覆盖该次恢复行为。没有可用文本时禁用该动作并解释原因，不自动粘贴空字符串。

### 7.4 文件引用分支

Q03 已选择只保存引用：保存文件 URL 与必要的可解析书签信息，按系统允许的能力尝试重新定位；书签不是文件内容，也不保证删除后恢复。恢复前检查存在性与可访问性；路径失效时显示“文件不可用”。解析得到的新位置是恢复时的派生值，不因重新定位就无版本地改写原始快照与内容摘要。

多文件中任一个不可用时，首期默认不静默粘贴剩余子集；保留历史并说明哪类问题阻止恢复。记录文件引用不扫描文件夹、不读取整个文件、不自动压缩归档。沙盒路线还需验证持久授权。

已拒绝替代项“保存文件副本”：需要增加归档事务、去重、预算和副本清理策略，会改变本期存储架构；不把文件 URL 类型改成 Data 就称为已实现。

已拒绝替代项“本期不支持文件”：用户已经选择文件引用，不能在实施中将其静默删掉，也不能只显示路径文本就称为支持文件恢复。

## 8. 隐私规则、来源归属与数据安全

### 8.1 过滤顺序

过滤必须发生在持久化、搜索文本生成、缩略图写盘和正文日志之前：

1. 用户全局暂停。
2. 用户排除应用。
3. transient、concealed、autogenerated 等特殊标记策略。
4. 支持类型和大小/项目限额。
5. 后续内容摘要、存储与展示。

忽略列表以 bundle identifier 为稳定键，名称和图标仅作显示。通过选择应用配置，不要求用户手写系统路径。

### 8.2 特殊标记

默认跳过 org.nspasteboard.TransientType、org.nspasteboard.ConcealedType 和 org.nspasteboard.AutoGeneratedType。支持必要的已知旧式保密/临时标记属于同一过滤契约，不形成自动密码识别承诺。

首期不提供“仍然保存保密内容”的隐藏开关；若未来需要，应重新评估搜索、预览、导出和磁盘保护。标记由来源应用提供，未标记的密码仍可能像普通文本，界面必须如实说明。

### 8.3 来源应用不是可信身份认证

来源可信度建议记录为 declared、foregroundHeuristic、unknown。org.nspasteboard.source 可以提供来源声明，但可以被其他应用伪造，只用于说明，不作为安全授权依据。

前台应用由系统工作区信息推断；不要求读取该应用窗口标题、浏览器页面内容或全部窗口列表。不能为了显示来源去新增屏幕录制或辅助功能读取需求。

排除规则使用明确匹配和保守回退：只要合理线索命中被排除应用就跳过。来源未知时无法可靠保证该应用的每次复制都会被排除，必须保留这个限制。

### 8.4 本地数据保护边界

建议首期不实现应用级密码锁与数据库加密，依赖当前 macOS 账户访问控制和用户设备的磁盘保护。此为可见范围决定，不能把“仅本机”宣传为数据库已加密。

同一用户权限下的其他软件可能读取本应用存储；日志、搜索文本和预览都是可能泄露内容的派生数据。首期禁止正文、URL 内容、文件完整路径和源应用窗口标题进入诊断日志。日志只保留时间、阶段、非内容 ID、字节计数、持续时间与错误码。

删除历史会删除应用可访问的记录和关联派生内容，但 SQLite 页、WAL、系统备份和存储介质的历史残留不构成安全擦除保证。不得用“删除”承诺法证不可恢复。

### 8.5 网络行为

产品运行不发起外部网络请求；不做链接抓取、远程图片、崩溃上传或遥测。开发工具下载依赖与运行中产品网络行为分别验证。系统自己的 Gatekeeper/签名查询流量不归属本应用产品网络功能。

## 9. 持久化、身份、去重与生命周期

### 9.1 建议决策：单一 Core Data 存储

使用 Core Data 的 SQLite 存储作为唯一事实来源，首期不建立第二个手动同步的正文搜索数据库。预览和搜索字段可以重建，不能成为恢复内容的唯一来源。

选项比较：

| 方案 | 优点 | 本期取舍 |
| --- | --- | --- |
| Core Data | 原生事务、关系、迁移和 UI 集成 | 选用；遵守 context 隔离和迁移限制 |
| SwiftData | 声明式集成简洁 | 可行，但没有本期强制收益，不同时引入两套持久层 |
| SQLite + 手写 SQL/GRDB | 模式和全文检索控制直接 | 如测量证明需要再重审；首期减少依赖和双写 |
| JSON/单大文件 | 初始实现简单 | 并发更新、大图片和部分写入恢复成本较高 |

### 9.2 概念数据模型

| 概念 | 关键字段与关系 | 不变量 |
| --- | --- | --- |
| ClipRecord | UUID、hashVersion、payloadHash、primaryKind、createdAt、lastCapturedAt、lastUsedAt、inHistory、byteCount | UUID 不由内容或时间推导；不以“使用过”代表对方粘贴成功 |
| SnapshotItem | record、position | 同一记录 position 唯一且顺序稳定 |
| Representation | item、typeIdentifier、position、data、byteCount | 原始字节不被预览覆盖；类型顺序保留 |
| SourceAttribution | 标识、显示名、可信度 | 可为空；不将推断伪装成确定 |
| Pinboard | UUID、名称、排序值 | 与记录生命周期分离 |
| Membership | record、pinboard、position、addedAt | 同一收藏夹中同一记录至多出现一次 |
| DerivedContent | 标题/文本预览、searchText、预览版本 | 可从原始内容重建，不承担备份职责 |
| ApplicationPreferences | 用户选择的容量、样式和动作默认 | 不保存明文授权凭据，不假装可以自行授予权限 |

大 Data 可以由 Core Data 的外部二进制存储选项管理。应用不自行把外置文件改名、移动或删除，不假定该选项必然把所有对象外置。由持久层管理事务和关联文件，避免首期额外引入手工 blob-store 的双写协议。

createdAt 为首次保存时间，lastCapturedAt 为最近一次实际外部复制时间，lastUsedAt 为用户最近发起恢复/粘贴时间。历史期限以 lastCapturedAt 计算，点击或粘贴不能延长期限；再次真实复制可重新获得历史资格，不改变收藏顺序。默认历史排序为 lastCapturedAt 降序，同时间按稳定 UUID 决定次序。

### 9.3 去重语义

2026-11-01 用户明确更新：去重仅依据复制内容，不因来源应用或附带 HTML/RTF 格式不同拆成多条。精确恢复负载摘要与业务去重键分开。

文本内容以来源提供的纯文本优先建立版本化身份，统一换行与 Unicode 标准等价形式，不忽略有意义的空格或大小写；同文的纯文本和富文本复制复用同一记录。文件按规范化文件引用识别，不用文件名或书签字节作身份，也不读取文件内容作全文件哈希。多项目保留项目次序和边界；图片等不属于纯文本/文件引用的负载保持精确表示匹配。

重复复制复用 UUID，createdAt 不变，刷新 lastCapturedAt、最新来源和最近复制的完整恢复表示，在历史中置顶；来源只是展示信息。收藏关系与收藏排序保留。首期不保存每次复制的完整事件日志。

新的去重键使用 SHA-256 和 hashVersion=2，不能依赖 Swift Hasher。升级时在一个事务中归并旧的同内容记录，保留最早记录身份/创建时间、最新复制时间和表示，合并收藏关系；同一收藏夹重复关系保留最前位置。迁移失败回滚并保留原库。摘要命中后仍比较内容身份以防异常冲突。精确负载摘要继续用于自身恢复识别，不与业务去重混用。

### 9.4 事务与操作语义

一次采集作为完整事务提交：记录、项目、表示和必要的搜索元数据一同成功。失败不能留下“卡片存在但原始内容不存在”的半份记录。UI 只将已提交记录称为“已保存”。

删除记录会删除其项目、表示和收藏关系，不删除收藏夹本身。删除收藏夹仅删除该收藏夹及关系，不删除仍属于历史或其他收藏夹的内容。

历史容量回收仅移除 inHistory；有收藏关系的记录继续保留。无历史资格且无收藏关系的记录才允许物理回收。清空历史保留收藏；单独的删除内容动作应说明它会影响收藏关系。

### 9.5 容量政策：建议默认

| 参数 | 默认建议 | 说明 |
| --- | --- | --- |
| 历史条数 | 1,000 条 | 收藏保留不受历史条数淘汰 |
| 历史期限 | 30 天 | 与条数共同作用，任一超限即可移出历史 |
| 原始有效负载预算 | 1 GiB | 逻辑字节预算，不是物理磁盘占用保证 |
| 派生预览缓存 | 128 MiB | 可丢弃重建 |
| 写入前可用空间门槛 | 512 MiB | 达到低空间状态时停止新增并说明原因 |

设置可选择无限条数或不限天数，但原始数据预算仍独立存在并在界面说明。预算清理先丢缓存、再淘汰最旧的非收藏历史；收藏占满预算时停止新增，提示用户处理，不暗中删除收藏。

数据库、WAL、索引、外置存储及文件系统分配会使实际磁盘使用高于原始有效负载字节。容量显示须区分逻辑数据和测得的目录占用。

### 9.6 数据迁移与损坏

每次持久模型升级定义版本与迁移前置检查。升级失败时保留旧库，进入可诊断的受限状态；不能捕获异常后删除数据库以“重新开始”。

备份采用 Core Data 支持的一致性方式或经验证的停写导出，不直接复制正在使用的单个 SQLite 文件而忽略 WAL。首期不承诺导入旧 Paste 数据，不触碰旧应用库。

正常退出先停止新采集，再结束进行中的短事务；不能无限等待不响应的系统读取。进程被强制结束后依赖已提交事务恢复，未提交的最新快照不保证保留。

## 10. 搜索和收藏交互

### 10.1 搜索契约

搜索覆盖保存的标题、可提取正文、来源应用名称；不因搜索访问网络或打开原文件。使用字面量子串匹配，避免把用户输入的百分号、下划线或正则元字符当作查询语法。

中文例子：“项目启动会议记录”必须能由“启动会议”查到。拉丁文本使用不区分大小写的匹配；对组合 Unicode 在派生字段中使用一致规范化，但不改变原始恢复数据。多词首期按整段字面量查询，除非 PRD 另行选择查询语言。

UI 输入去抖建议 100ms。查询返回不可变结果页，默认每页 100 项，并有稳定次序；输入发生变化时旧查询结果不能覆盖新查询。分页和结果更新不能重置用户正在操作的选择。

### 10.2 搜索索引选择

首期使用同一存储中的派生文本，不默认依赖英文分词或 FTS。只有在代表性数据上无法满足延迟目标时，才评估中文分词、trigram 或独立可重建索引。索引重建失败不能删除原始历史。

### 10.3 Pinboard

建议支持创建、重命名、用户排序及在多个收藏夹中保存同一条记录。收藏夹内顺序与历史最近复制顺序分别保存，重复复制不打乱用户收藏排序。

解除固定只删除选定关系；若条目已被历史容量淘汰且不再属于任何收藏夹，可回收。删除收藏夹的确认文案必须描述关系变化，不误称永久删除所有内容。

快捷键切换收藏夹按用户可见顺序循环；无收藏夹时动作保持无副作用并可显示提示。快速编号粘贴在本期后置，首期不注册 ⌘1…⌘9 作为全局编号动作。

## 11. 权限状态及能力降级

### 11.1 独立状态

| 能力 | 状态来源 | 允许的结果表达 |
| --- | --- | --- |
| 程序读取剪贴板 | 新系统 accessBehavior、实际读取结果、版本支持情况 | allowed、ask、denied、unknown；未知不是已允许 |
| 全局快捷键 | 注册调用及错误 | registered、conflict、unavailable |
| 自动粘贴 | 相关系统检查、实际目标路径 | permitted、needsPermission、unknown |
| 登录启动 | SMAppService.status 或明确的系统手动配置结果 | enabled、notRegistered、requiresApproval、notFound、failed |
| 存储 | 持久层可用性和实际事务 | writable、lowSpace、migrationFailed、writeFailed |

不读取或写入系统 TCC 数据库作为产品权限判断接口。诊断时期只读看到的旧记录不是产品可依赖的公开契约。

### 11.2 读取权限

新 SDK 可调用 NSPasteboard.accessBehavior；用编译可用性和运行时可用性正确分支。权限未知或版本不支持时，不将空内容误判为拒绝，也不为了“测试权限”持续触发系统提示。

首次运行先说明持续记录用途，由用户启动记录流程。系统提示由实际公开接口触发；应用不能把 accessBehavior 设置为 alwaysAllow。权限变化后，在回到应用或用户主动重试时刷新状态，避免高频轮询系统设置。

### 11.3 快捷键与输入监控

建议使用 KeyboardShortcuts 的专用快捷键注册路线，允许用户录制并报告冲突。首期不为呼出面板注册全键盘事件监听器；不把输入监控设为普通记录和呼出流程的共同前置条件。

如果后续功能确实改为事件 tap，必须另行记录其目的、权限和失效恢复，不能仅为了绕过快捷键注册冲突就监听所有按键。

### 11.4 自动粘贴权限

使用公开控制/发送事件检查，例如 CGPreflightPostEventAccess，配合用户发起的授权路径；具体 API 与 macOS 版本在实施时核验。设置 UI 使用系统认可的名称，兼容新版“设备控制与数据访问”等显示名，避免硬编码旧中文路径作为唯一入口。

没有控制权限时，历史查询、收藏和恢复系统剪贴板仍可使用。用户明确选择自动粘贴才引导相应授权，不在启动时一次索取无关权限。

### 11.5 权限恢复不是静默重置

提供“打开系统设置”“重新检查”和必要的重新启动说明。产品不自动执行 tccutil reset，不删系统授权记录，不要求用户提供系统密码给应用。不假定设置开关看似打开就等于当前构建身份已获信任。

## 12. 恢复、自动粘贴与焦点状态机

### 12.1 两种操作分别定义成功

恢复剪贴板：写入全部选定项目及表示成功，必要时读回可验证的类型/数据摘要。它只证明系统剪贴板准备完成。

自动粘贴：先完成恢复，再尝试恢复目标应用焦点并发送 ⌘V。产品可以报告“已发送粘贴操作”，不能无依据地报告“目标应用已插入”。只有用户观察或可访问的测试接收端能证明插入结果。

lastUsedAt 表示用户发起恢复或粘贴的时间，不命名为 lastSuccessfulPasteAt。

### 12.2 状态机

~~~text
idle
  → preparing(record, mode, target)
  → clipboardWritten
     ├→ completedRestore
     └→ checkingTarget
        ├→ needsPermission
        ├→ targetUnavailable
        ├→ focusChanged
        └→ activatingTarget
           → verifyingForeground
              ├→ cancelled
              └→ eventPosted
~~~

每次操作有不可复用的 generation。新的操作、用户取消或目标变化会使旧回调失效，避免延迟任务向错误应用发出按键。

### 12.3 目标与焦点

呼出面板前记录前台 NSRunningApplication 的进程身份。不能仅凭 bundle identifier 重新选择另一个实例，也不能在用户切换到别的应用后继续执行旧意图。

用户提交后隐藏面板，按公开激活机制请求目标获得焦点，并有限等待实际前台状态。建议总等待上限 1 秒；没有成功就保留准备好的剪贴板并提示手动粘贴，不盲目延时后发送。

确认目标仍存在，前台是预期进程，用户发起快捷键所用修饰键已释放或在有限等待内释放。构造明确的 ⌘V keyDown/keyUp 事件，不能把呼出快捷键残留的 Option/Shift 带到目标动作。

系统没有提供跨应用的原子“锁定焦点并粘贴”事务；检查与发送之间仍有极短调度窗口。实现必须取消所有已观察到的目标变化并尽量缩短窗口，不能宣称对任意并发时序有数学上的零误投保证。

密码框、远程桌面、特殊编辑器或应用自己的粘贴逻辑可能拒绝或修改内容。首期不承诺对每个接收程序都能自动插入，不通过任意 AppleScript 或菜单注入追求兼容。

### 12.4 自身写入与竞争

写入操作记录该次内部来源标记、完成后的计数和有效负载摘要，采集端只跳过匹配的本次自身恢复。不得永久忽略所有“内容相同”或“来源是自己”的未来复制。

与其他应用同时写入时，系统剪贴板没有给本应用通用的事务锁。恢复失败、发现竞争或用户随后复制新内容时，停止自动粘贴，不重新覆盖用户最新内容。

不在固定延时后无条件恢复操作前的旧剪贴板：目标应用可能尚未读取，且用户可能已复制新内容。首期默认保留用户选择恢复的内容。

### 12.5 多选

首期建议一次操作选一条历史记录；一条记录内部的多个剪贴板项目仍完整恢复。跨多条历史批量拼接、连续 Paste Stack 和自动多次按键属于后续能力，不能与多项目快照混淆。

## 13. 后台运行、登录启动与恢复

### 13.1 正常常驻

主 app 设置 LSUIElement，持有菜单栏项、recorder 和持久层的强引用。关闭历史面板或设置窗口不终止进程；用户从菜单选择退出才结束应用。UI Scene 的销毁不应顺带释放唯一的计时器所有者。

应用必须有明确的退出入口。若用户隐藏菜单栏图标，则重新打开已安装应用应立即恢复一个可见入口或显示面板，避免“图标隐藏且快捷键冲突后无法进入设置”。

### 13.2 计时器与 App Nap

计时器加入适合的 RunLoop 模式，验证拖动、菜单跟踪或其他 UI 交互不会无意停止采集。不可根据主进程存在推断它仍按预期间隔运行。

默认不申请禁止系统休眠、不播放静音音频、不运行忙循环，也不使用 caffeinate 冒充后台设计。先以真实后台复制测量调度延迟。仅在必要时对用户明确开启的记录工作建立范围清楚的 ProcessInfo activity，允许 idle system sleep；暂停、退出和不再需要时成对结束。

activity 使用与否必须由数据支持，不能在没有测量时全局关闭 App Nap。能耗与稳定复制验收同时成立才算通过。

### 13.3 登录启动

使用 SMAppService.mainApp。开关动作应区分“用户希望开启”与系统返回的真实注册状态；requiresApproval 时引导系统设置，failed 时展示错误，不先把开关显示为成功。

登录启动默认关闭，由用户主动选择。在本机固定安装位置完成注册和验证，不能拿 DerivedData 中的一次运行代表已安装副本的登录行为。

普通主 app 注册登录项不应被描述为崩溃守护。Apple 文档对某些 helper 的重启描述不能推广到 mainApp。首期不因主进程退出而自动强行重启，用户明确退出后同一会话保持退出。

如本地签名与平台组合确实不支持应用内注册，允许提供系统手动添加本 app 的步骤作为本机使用的降级方式；记录方法和实际登录结果，应用不得声称已完成它无法验证的注册。

### 13.4 系统事件

| 事件 | 动作 | 持久语义 |
| --- | --- | --- |
| 用户暂停 | 停止新采集、释放记录活动声明 | 保存暂停选择 |
| 系统将睡眠 | 停止无意义工作，保留已提交数据 | 不改写用户暂停选择 |
| 唤醒 | 刷新状态、重启有效调度、检查当前内容 | 不补造中间历史 |
| 会话切换或锁屏 | 暂停可疑的主动操作，禁止延迟自动粘贴 | 不将其他用户会话作为当前目标 |
| 返回前台 | 刷新权限、自启和存储状态 | 不反复弹出授权提示 |
| 磁盘低空间 | 停止新增、保留查询与恢复 | 不清空旧数据 |
| 升级迁移失败 | 进入受限模式并解释 | 保留旧库及错误信息 |
| 用户退出 | 停止调度，结束短事务，释放资源 | 下次启动恢复用户设置 |

### 13.5 崩溃与强制退出边界

首期保证可重新打开并读取已提交内容，不保证崩溃到用户重启应用之间继续采集。强制退出期间的内容丢失属于停止运行的后果，应在文档说明。

若未来确实需要 UI 崩溃后 recorder 仍运行，重新评估双进程与 IPC、签名、权限归属及唯一写入者；不得临时添加互相拉起的看门狗。

## 14. 面板、交互和设置

### 14.1 面板默认方案

建议采用接近 Paste 的屏幕底部横向卡片面板，在鼠标所在的有效显示器显示，保留搜索框、历史/收藏切换与键盘导航。屏幕定位和尺寸属于可调 UI 默认，不锁定旧应用像素或素材。

使用 NSPanel 管理位置、层级和焦点；SwiftUI 展示卡片内容。是否使用 nonactivatingPanel 必须通过文本输入、输入法组合和焦点回归验证，不把“不会激活 app”误解为“不会影响键盘焦点”。

面板不得使用长期覆盖安全对话框的窗口层级。多屏时应依据有效 NSScreen 和 visibleFrame 定位，不缓存已经断开的 display identifier。

### 14.2 键盘行为

- 呼出快捷键由用户配置，首启提供录制入口，不无提示抢占系统或其他应用组合。
- 面板内方向键移动选择，Return 按当前默认方式恢复/粘贴，Escape 关闭。
- 提供明确的“仅复制到剪贴板”和“纯文本”动作。
- 前后收藏夹切换按可见顺序；输入法组合期间不拦截文本编辑相关操作。
- 面板未出现时不占用 ⌘1…⌘9；快速编号粘贴默认后置，避免把泛称“快捷键”扩大为更多全局拦截。
- 错误提示不能抢占正在输入的目标应用焦点。

### 14.3 状态展示

用户至少能看到：记录开启/暂停/受限、快捷键已注册/冲突、自动粘贴可用/需授权、登录启动实际状态、存储状态。最后检查时间、最后保存时间和最后写入错误分开，不能以“进程运行中”代替这些信息。

未出现新内容不自动归因于权限：可能因为没有复制、被排除、格式不支持、超限、自身恢复、来源程序临时数据或写入失败。诊断页面给出原因类别及计数，不显示被过滤的正文。

## 15. 实施环境、依赖和交付物

### 15.1 系统支持

Q01 已选择本机自用，验收基线为用户当前 arm64 Mac、macOS 27.0.1（实施时再次记录实际版本）。首期不承诺 Intel、旧版系统或其他硬件。构建为原生 arm64，避免把旧 Intel 应用的 Rosetta 路径带入新产品。

构建使用能支持目标系统和所需接口的完整 Xcode。部署目标与 SDK 选择由实施阶段确认，但最低支持目标不能低到引入本期未验证的兼容分支。应用不得仅因为本机有旧 Command Line Tools 就固定在旧 SDK。

### 15.2 依赖

原生框架为 AppKit、SwiftUI、Core Data、ServiceManagement、CoreGraphics、CryptoKit 和 OSLog。KeyboardShortcuts 作为全局快捷键候选依赖，在实际选择时核对支持版本、许可证和锁定版本；不因文档中的仓库链接自动追随 main 分支。

用户已选择本机自用；候选实施以非沙盒原生 app 为起步，不添加云、推送和商店能力。TCC 仍适用。非沙盒不代表可跳过系统控制授权或任意读取受保护文件。

### 15.3 安装与数据位置

新应用名称、标识及数据目录与 Paste 分开。建议在用户确定的固定 Applications 位置安装一份验收副本，避免同时运行调试版与安装版导致权限和数据归属混淆。

app bundle 内不保存用户历史、日志或运行状态。通过系统的 Application Support、Caches 和偏好存储接口定位数据，不能把 /tmp 当正式历史库。/tmp 仅是本次文档目录。

## 16. 可靠性、资源和可观察性目标

以下为待实现后验证的工程目标，不是测量结论。若达不到，先分析原因并记录取舍，不能改写日志为成功。

| ID | 指标 | 比较与阈值 | 数据来源与观察窗口 |
| --- | --- | --- | --- |
| PERF-01 | 稳定文本从复制到提交可查的延迟 | p95 ≤ 1,000ms；100/100 完整保存 | 本机正常负载，100 次不超过 1KiB 的独特文本，每次保持至少 2 秒，记录复制和提交时间，单次约 4 分钟 |
| PERF-02 | 历史面板从快捷键收到到可交互 | 暖启动 p95 ≤ 250ms | 100 次开关、5 分钟，现有应用事件与面板呈现观测，排除首次授权对话框 |
| PERF-03 | 本地搜索从输入稳定到结果显示 | p95 ≤ 200ms，包含建议 100ms 去抖 | 1,000 条代表性文本历史，50 条查询含中文、拉丁及特殊字符，3 分钟；报告包含去抖的完整延迟 |
| PERF-04 | 空闲 CPU | 10 分钟平均 ≤ 单逻辑核的 1% | 面板隐藏、无剪贴板变化、同步不存在；Activity Monitor / Instruments 同一口径 |
| PERF-05 | 稳态内存 | 1,000 条历史、面板关闭后 60 秒，resident ≤ 250MiB | 用现有 ps 的 rss 字段取 KiB，换算 MiB；记录系统/构建/数据组成，不混用 Activity Monitor 的其他内存口径 |
| REL-01 | 已提交记录的重启可恢复性 | 100/100 记录及原始表示一致 | 正常退出重开一次、一次受控进程终止后的重开；对比记录 ID 与摘要，不输出正文 |

真实图片/富文本/文件恢复的正确性优先于上述文本性能。快速复制实验单独报告，不把 PERF-01 的 2 秒稳定窗口挪用为“300ms 内任意复制都不会漏记”。

### 16.1 诊断字段

建议最小字段：操作 ID、记录非内容 UUID、阶段、成功/失败类别、持续时间、项目数、表示数、字节数、系统版本、构建版本。诊断默认本地保存，轮转和总量上限建议 10MiB。

不记录用户搜索词、片段正文、文件完整路径、原始 URL、源应用文档标题或二进制字节。测量若需要合成内容，明确标为合成样本，不能拿用户历史作为公开报告素材。

### 16.2 故障定位顺序

检查进程与用户暂停状态 → 调度是否实际运行 → 读取策略 → 剪贴板计数是否变化 → 过滤原因 → 快照一致性 → 持久提交 → 查询/面板 → 写回剪贴板 → 目标焦点 → 自动发送权限 → 接收端实际行为。

每一步的观测只证明该步，不将“进程存在”“写入返回 true”或“CGEventPost 已调用”当成端到端成功。

## 17. 思想实验与竞争解释检查

| 情境 | 容易做错的解释或修复 | 本草案的处理 |
| --- | --- | --- |
| 能保存但按快捷键没有面板 | 反复要求剪贴板权限 | 查看快捷键注册、面板位置和显示器状态 |
| 能看到历史但双击不插入 | 认为记录失败 | 分开验证写回、焦点、事件发送和接收端 |
| 后台进程活着却漏记 | 加一个 root 守护进程 | 测量 timer、App Nap、读取阻塞及复制速度 |
| 两轮间复制三次 | 按计数增量生成三条相同记录 | 只保存实际读取的稳定快照并承认中间丢失 |
| 同文字不同格式 | 按纯文本摘要合并 | 摘要考虑实际恢复表示 |
| 复制密码但没有 concealed 标记 | 宣称已自动保护所有密码 | 说明标记限制，允许暂停和按应用排除 |
| 来源声明伪造 | 把声明作为安全身份 | 只作展示，排除规则保守处理并标明未知 |
| 读取中其他应用改了剪贴板 | 把一半旧格式一半新内容存下 | 前后计数比较，有限重试 |
| 自动粘贴等待期间用户切换应用 | 固定延时后盲发 ⌘V | generation 作废，检查前台，取消 |
| 恢复后用户复制新内容 | 再把旧剪贴板强行写回 | 不执行无条件回滚 |
| 收藏条目超过历史容量 | 淘汰原始内容留下空收藏卡 | 历史资格与收藏持有分离 |
| 删除收藏夹 | 连带删除其他夹或历史的记录 | 仅删该夹关系，按持有关系回收 |
| 文件被删或权限变化 | 仍显示“已备份，可恢复” | 引用失效明确提示，不声称保存副本 |
| 数据库迁移失败 | 删除旧库让应用启动 | 保留原数据，报告受限状态 |
| 只复制活动 SQLite 文件备份 | 将缺少 WAL 的副本当完整备份 | 使用一致性导出或经过验证的停写备份 |
| 重编译后开关仍亮但权限失效 | 相同 Bundle ID 就认定已授权 | 对比代码身份并做真实权限检查 |
| 用户退出后立即又启动 | 认为“永远保活”是可靠性 | 尊重退出，不添加互拉看门狗 |
| iCloud 不做但保留远程依赖 | 让用户仍须配置容器/登录 | 删除本期云链路、能力和设置 |

## 18. 验证策略与验收取证

### 18.1 已有验证面与当前限制

当前没有新应用源码、测试 target、UI 自动化或构建产物。现有可用验证面为 macOS 系统剪贴板、TextEdit、Finder、浏览器输入框、System Settings、Activity Monitor、Instruments 及标准签名检查工具。

验收首先通过新应用正常入口与这些现有系统路径完成，不为了填表创建隐藏导入入口、替代 recorder、私有测试协议或独立演示 app。未来确有必要的回归测试应针对正确接口，并明确覆盖局限。

### 18.2 核心真实路径

1. 在 TextEdit 输入唯一、非敏感文本并复制。
2. 新应用在后台采集，打开历史后能查到。
3. 用包含中文的子串搜索定位。
4. 收藏、重新排序、退出并重开验证持久性。
5. 仅恢复剪贴板后，在另一个文档手动 ⌘V，核对内容。
6. 自动粘贴到预先选择的目标文档，核对接收端实际内容。
7. 以网页富文本、图片、链接、Finder 多文件引用重复对应步骤。

每种类型至少含普通样本、支持子集边界和不可恢复样本。不得把截图中出现了一张卡片作为原始数据可恢复的唯一证据。

### 18.3 权限、状态与生命周期

分别测试首次安装、拒绝读取、拒绝控制、撤销授权、同 Bundle ID 重编译替换、用户暂停、图标隐藏、快捷键冲突、面板关闭、睡眠唤醒、外接屏断开及用户退出。

会改变系统权限、强制终止应用、退出登录、重启或模拟低磁盘状态的验证，应在后续实施任务授权的具体环境和时间窗口执行；当前文档任务不执行这些操作。权限测试只改变本应用的必要设置，不重置全系统授权。

### 18.4 静态与包级检查

对未来构建产物使用现有 codesign、plutil、file 和 otool 检查：新身份、原生架构、有效签名、LSUIElement、无 CloudKit 能力、无远程同步依赖和无旧 Paste 数据目录配置。依赖源代码中没有某个词不能单独证明运行时绝不联网。

若检查本地签名种类，分别报告结构完整性和平台接受结果；自签名/临时签名不能被描述为已经公证。

### 18.5 结果报告

报告每项验收的系统版本、构建身份、步骤、预期、实际结果及证据位置；失败保留具体错误，不写成“多数路径看起来没问题”。没有执行的项目标为未验证。

## 19. 实施顺序与风险控制

以下是架构内的阶段顺序，不是已经授权的实施 issue。

| 阶段 | 应交付的可观察结果 | 进入下一阶段条件 |
| --- | --- | --- |
| M0 环境、身份与系统接口 | 完整 Xcode 位置已确认；本机候选 app 能启动；本地签名、必要控制授权与登录启动可验证 | 无付费账户硬依赖；失败有明确限制与可用本机路径 |
| M1 文本闭环 | 正常复制 → 保存 → 搜索 → 恢复 → TextEdit 手动粘贴 | 对正文一致、重启恢复和暂停行为有证据 |
| M2 格式和过滤 | 富文本、图片、链接、文件引用以及特殊标记规则 | 原格式恢复及前置隐私过滤通过 |
| M3 面板、收藏和动作 | 可用面板、快捷键、Pinboard、纯文本与自动粘贴 | 目标应用结果、焦点竞争和权限降级通过 |
| M4 生命周期与容量 | 登录启动、唤醒、限额、清理、错误状态 | 不删除收藏、不破坏旧库、后台能力与能耗达标 |

M0 是技术事实验证，不是要求另建一个长期维护的实验产品。优先从最终应用的真实入口实现最薄路径；仅在无法区分平台限制时才提出最小临时实验及其必要性。

主要风险包括：本地签名的信任延续、平台权限变化、App Nap 调度、pasteboard 同步读取阻塞、接收端格式差异、文件引用失效、大对象内存、数据迁移和收藏空间耗尽。每项风险在前述契约中都有可观察失败路径，不能仅靠异常捕获隐藏。
